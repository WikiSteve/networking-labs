Set up the three local accounts

Choose GUI or commands, not both. Use practice passwords that you can remember. Do not use real passwords.

GUI route: Press Windows+R, type lusrmgr.msc, and press Enter. This opens Local Users and Groups.

  1. Select Users, then Action > New User.
  2. Enter LabAdmin as the user name and enter its practice password twice.
  3. Clear User must change password at next logon. Select Create.
  4. Repeat for Alice and Bob, then select Close.
  5. Open LabAdmin's properties. Select Member Of > Add. Type Administrators, select Check Names, then OK > Apply. Leave Alice and Bob as standard users.

If LabAdmin already exists, skip creating it and changing its membership.

Command route: Open Start, type cmd, right-click Command Prompt, and select Run as administrator. Approve the prompt.

net user LabAdmin * /add
net localgroup Administrators LabAdmin /add
net user Alice * /add
net user Bob * /add

If you are reusing an existing LabAdmin account, run only the last two commands.

For net user, /add creates an account. The * asks you to enter the password twice without displaying it. For net localgroup, /add adds the named account to that group. Here it makes LabAdmin an administrator.

Check the roles

GUI: In Local Users and Groups, open Groups > Administrators. LabAdmin should be listed; Alice and Bob should not. Open Groups > Users to check Alice and Bob are present.

Commands:

net localgroup Administrators
net localgroup Users

Other built-in or existing entries are normal. No screenshot is needed here.

Understand the idea before you click

Permissions versus encryption. NTFS permissions (the Security tab) are rules Windows checks before it opens a file: "Bob may read this folder." An administrator can change those rules. Encryption scrambles the file's contents. Without the right key, the contents stay unreadable, even when the permissions say "allowed".

EFS versus BitLocker. BitLocker encrypts the whole drive. It protects data when the computer is off, lost or stolen. Once the drive is unlocked, Windows permissions still control which files each signed-in user can access. EFS (Encrypting File System) encrypts individual files for authorized users. In this lab, only Alice has a key, so it still protects them from other people signed in to the same running computer. Many organizations use both.

Where the key comes from

When Alice encrypts a file, Windows creates an EFS certificate for her. The certificate contains her public key. Windows keeps the matching private key separately in her profile. Windows locks the file with a random file key, then locks that file key with Alice's public key. Only Alice's private key can unlock it. Windows stores the private key in Alice's profile and protects it with her password. Your key backup is a PFX file: the certificate plus the private key, protected by a password you choose. A .cer file holds only the certificate, so it cannot decrypt the file by itself.

Encrypt and back up

Sign in asAlice

What to capture for Screenshot 1

Sign in as Alice using her local account password.

Make the mission folder

In File Explorer, select View > Show > File name extensions so you can see .txt and .pfx.

Alice uses Public Documents, a folder Windows shares with every local user. Bob and LabAdmin should be able to read plain files here. Both new files inherit the folder’s permissions. Reading the plain control file will confirm access before you test the encrypted file.

Choose one route.

GUI route: Open File Explorer. Click the address bar, type C:\Users\Public\Documents, and press Enter. Right-click empty space and select New > Folder. Name it EFS-Lab and open it.

Right-click empty space and select New > Text Document. Name it public (Windows keeps the .txt ending). Open it, type the text below, save with Ctrl+S and close Notepad:

PUBLIC NOTICE: Book club meets Thursday. Snacks provided. Everyone welcome.

Make a second text document the same way. Type secret for its name; Windows keeps the .txt ending. Check that Explorer displays exactly public.txt and secret.txt, not names ending in .txt.txt. Put this text in the secret:

TOP SECRET: The golden stapler is hidden behind rack 3. Trust no one. - Agent Alice
Prefer Command Prompt? Use this route instead

Command route: Open Command Prompt (not as administrator).

cd C:\Users\Public\Documents
mkdir EFS-Lab
cd EFS-Lab
echo PUBLIC NOTICE: Book club meets Thursday. Snacks provided. Everyone welcome. > public.txt
echo TOP SECRET: The golden stapler is hidden behind rack 3. Trust no one. - Agent Alice > secret.txt

echo prints the text, and > saves it into the named file instead of the screen.

Finish your text before encrypting. Do not edit secret.txt afterward.

Encrypt only secret.txt

Choose one route.

GUI route: Right-click secret.txt and select Properties. Select Advanced. Check Encrypt contents to secure data. Select OK, then Apply.

Windows shows an Encryption Warning because the folder itself is not encrypted. Select Encrypt the file only, then OK twice.

Prefer Command Prompt? Use this route instead

Command route:

cd C:\Users\Public\Documents\EFS-Lab
cipher /e secret.txt

cd changes to the mission folder; /e means encrypt. cipher encrypts just the file you name.

Why file only? Encrypting the folder would make new files there encrypted too. Alice's notice must stay readable, so EFS-Lab and public.txt stay plain.

If Windows offers a key-backup notification, you can close the notification and follow the backup steps below.

Check the result

GUI route: Look at the icons. secret.txt shows a small padlock; public.txt does not. For a closer look, open secret.txt's Properties > Advanced > Details: expect only Alice under users who can access the file, with no recovery certificate. If a recovery certificate is listed, ask your instructor before the reset test.

Prefer Command Prompt? Use this route instead

Command route:

cd C:\Users\Public\Documents\EFS-Lab
cipher

cd changes the current folder. With no options, cipher lists that folder. Expect E secret.txt (encrypted) and U public.txt (unencrypted).

Open secret.txt. Alice can read it normally because Windows unlocks her private key automatically.

Back up Alice's key

Alice's private key lives only in her profile. Save a copy in a PFX file on her Desktop. The Desktop is outside the encrypted file and is not encrypted itself.

Choose one route.

GUI route: Press Windows+R, type certmgr.msc, and press Enter. This opens Alice’s user certificates.

  1. Open Personal > Certificates. Select the certificate whose Intended Purposes includes Encrypting File System.
  2. Right-click it and select All Tasks > Export.
  3. Select Next, then Yes, export the private key, then Next. If this option is unavailable, stop and ask your instructor.
  4. Keep Personal Information Exchange (.PFX). Do not select Delete the private key if the export is successful. Select Next.
  5. Select Password, enter the backup password twice, then Next.
  6. Select Browse, choose Desktop, and name the file alice-efs.pfx. Select Save > Next > Finish.
  7. Expect The export was successful.
Prefer Command Prompt? Use this route instead

Command route: Open Command Prompt (not as administrator). The full path below saves the backup to Alice’s Desktop, wherever your command window started.

cipher /x C:\Users\Alice\Desktop\alice-efs

/x exports Alice's current EFS certificate and private key. Confirm the Windows prompt, then type the backup password twice. Windows adds .pfx to the name.

Expect alice-efs.pfx on the Desktop. If the file is missing or the export failed, stop here: do not reset Alice’s password until you have the backup. In real life, move a PFX to a USB drive or safe storage, because anyone holding it and its password can open Alice's files.

Can Bob read it?

Sign in asBob

What to capture for Screenshot 2

public.txt is your control file. It sits in the same folder as secret.txt but is not encrypted. If a person can read it, Windows permissions let that person into the folder. Both files were created in the same folder with inherited permissions. The expected difference is that EFS also requires Alice’s private key for secret.txt.

Sign in as Bob. Skip any PIN or Windows Hello offer.

Choose one route.

GUI route: In File Explorer, go to C:\Users\Public\Documents\EFS-Lab. Notice the padlock: Bob can see that the file is encrypted, and its name and size, but not its contents. Open public.txt. Bob can read the notice. Now open secret.txt. Expect an error such as Access is denied. Open Start so Bob's name shows, then take the screenshot.

Prefer Command Prompt? Use this route instead

Command route: Open Command Prompt.

cd C:\Users\Public\Documents\EFS-Lab
whoami
type public.txt
type secret.txt

whoami shows the signed-in account. type prints a file. Expect the public notice, then Access is denied for the secret.

If Bob cannot read public.txt either, the test cannot separate permissions from encryption. Stop and ask your instructor.

Can the administrator read it?

Sign in asLabAdmin

LabAdmin tries

Sign in as LabAdmin. Administrators can override almost any permission. Find out whether that is enough.

Choose one route.

GUI route: Go to the EFS-Lab folder. Open public.txt; LabAdmin can read it. Open secret.txt. Expect an access error. Open Start so LabAdmin's name shows, then take the screenshot.

Prefer Command Prompt? Use this route instead

Command route: Open Command Prompt as administrator. The window title starts with Administrator:, showing that full administrator rights are active.

cd C:\Users\Public\Documents\EFS-Lab
whoami
type public.txt
type secret.txt

Expect the public notice, then Access is denied.

An administrator can change permissions, move files or take ownership. None of that gives LabAdmin Alice's private key, so the contents stay scrambled. A recovery agent is an extra key some organizations configure so IT can recover encrypted files. If your chosen VM has one configured, its recovery behaviour can differ from this experiment.

Pause for a quick check

You can answer these before trying the next account. They are practice, not extra submission requirements.

Bob can read public.txt. Why might secret.txt still fail?

The files inherit the same folder permissions, but the encrypted file also requires a matching EFS private key. Bob does not have Alice’s key.

Would a certificate-only CER recover Alice’s file?

No. Recovery needs the matching private key. Alice’s password-protected PFX backup includes that private key as well as her certificate.

After importing the PFX, is secret.txt unencrypted?

No. Alice can read it because her key is available again. Verify that the file still shows EFS encryption.

Step 4 of 5 · 7 minutes

Reset Alice’s password

Sign in asLabAdmin → Alice

What to capture for Screenshot 4

Change versus reset

A password change happens when Alice types her old password and then a new one. Windows uses the old password to re-protect her private key, so her encrypted files keep working.

A password reset happens when an administrator sets a new password without knowing the old one. Windows cannot re-protect Alice's private key, so her new password may no longer unlock it. That is a safety feature: otherwise any administrator could reset Alice's password, sign in as her and read her files. On a standalone computer with local accounts, a key backup is Alice's way back.

LabAdmin resets Alice

Alice must be signed out. You signed her out after encrypting and backing up her key.

Choose one route.

GUI route: Press Windows+R, type lusrmgr.msc, and press Enter. Select Users. Right-click Alice and select Set Password. Read the warning about possible loss of information, such as encrypted files. Select Proceed, type Alice's new password twice, and select OK.

Prefer Command Prompt? Use this route instead

Command route: In Command Prompt as administrator:

net user Alice *

Type the new password twice. This command does not show the warning dialog that the GUI route displays.

Restart the VM: Start > Power > Restart. A restart makes sure no old Alice session remains.

Alice comes back

Sign in as Alice with her new password.

Choose one route.

GUI route: In File Explorer, go to C:\Users\Public\Documents\EFS-Lab. Open public.txt; Alice can still read it. Open secret.txt freshly from File Explorer. Expect an access error. Close any restored Notepad tab first: cached text is not a fresh file read. Open Start so Alice's name shows, then take the screenshot.

Prefer Command Prompt? Use this route instead

Command route: Open Command Prompt (not as administrator).

cd C:\Users\Public\Documents\EFS-Lab
whoami
type public.txt
type secret.txt

Expect the public notice, then Access is denied. The file still names Alice's certificate, but her new password cannot unlock the old private key.

If the secret opens instead, the reset did not remove Alice's key access. Do not fake the error. Ask your instructor; the VM may have different key-recovery or account settings. Do not delete certificates to force a failure.

Step 5 of 5 · 5 minutes

Restore Alice’s key

Sign in asAlice

What to capture for Screenshot 5

Restore the key

Choose one way to open the Certificate Import Wizard:

  • Double-click alice-efs.pfx on the Desktop, or
  • Press Windows+R, type certmgr.msc, and press Enter. This shortcut opens Alice's own certificates. Right-click Personal and select All Tasks > Import, then browse to the Desktop. Change the file type list to Personal Information Exchange so alice-efs.pfx appears.

Complete the wizard:

  1. If asked for Store Location, choose Current User, then Next.
  2. Check that the file name points to alice-efs.pfx. Select Next.
  3. Type the backup password. Leave the other options as they are. Select Next.
  4. Accept the suggested certificate store (Automatically select or Personal), then Next.
  5. Select Finish. Expect The import was successful.

Current User matters: it puts the key in Alice's own profile, where EFS looks for it.

Read the secret again

Choose one route.

GUI route: Open secret.txt. Expect the mission text. Look at the padlock on its icon: the file is still encrypted. Alice simply has her key back. Open Start so Alice's name shows.

Prefer Command Prompt? Use this route instead

Command route: In Command Prompt:

cd C:\Users\Public\Documents\EFS-Lab
whoami
type secret.txt
cipher

Expect the mission text, then E secret.txt and U public.txt.

If access is still denied, sign Alice out and back in, then try again.
